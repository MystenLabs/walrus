Walrus Sites v2.10.0​

June 4, 2026 | GitHub

Portal aggregator timing rework: a per-attempt fetch timeout plus a Bun idleTimeout sized from the worst-case retry budget close the gap where a slow aggregator could trip the inbound connection mid-flight and surface a generic upstream proxy error instead of the portal's own aggregatorFail() page. Sui and Walrus deps bumped to their current testnet releases. No Move contract changes.

ℹ️ Portal operators: each aggregator attempt is now bounded at 10s and fails over to the next URL; Bun's idleTimeout is sized from the full retry chain so the portal can return its own response. Tune via AGGREGATOR_REQUEST_TIMEOUT_MS (default 10000) and PORTAL_IDLE_TIMEOUT_MAX_S (default 100); resolved values logged at startup.

Changes​

  • portal: Size Bun idleTimeout from aggregator retry budget; add per-attempt fetch timeout and sanitize-and-log resolved config at startup
  • site-builder: Bump Sui to testnet-v1.73.0, Walrus to testnet-v1.50.0

Walrus Sites v2.8.0​

April 2, 2026 | GitHub

This release adds server-side redirect support to Walrus Sites. Redirect rules are stored as dynamic fields on the on-chain Site object, configurable via ws-resources.json with glob pattern matching. The portal evaluates redirects before resource fetching and serves 3xx response.

This release includes a Move contract upgrade — the walrus_site package is upgraded to add redirect storage on-chain. To use the new redirects feature, update the package_id in your sites-config.yaml to point to the latest package ID, or remove the package_id field entirely so that MVR can resolve it automatically.

Portal config change: site_package has been renamed to original_package_id as this is what actually matters of it.

The portal has also been updated to Mysten SDK v2.

Changes​

  • move/site-builder/portal: Support server-side redirects
  • server-portal: Drop blobOrPatchId and path labels from aggregator histogram
  • site-builder: Clear checkout credentials before pushing with automerge token
  • site-builder: Auto-detect Sui version when bumping Walrus alone
  • site-builder: Use automerge token for git push to trigger CI on version bump PRs
  • e2e: Build site-builder from main instead of using suiup
  • portal: Update portal deps to Mysten SDK v2
  • testing: Add a script for testing normal snake operation
  • move/site-builder: Update package ids after upgrade

Walrus Sites v1.1.0​

September 8, 2025 | GitHub

This release introduces a new publishing and deployment method for Walrus Sites using quilts instead of blobs. Multiple resources are now bundled as quilt patches on Walrus, significantly reducing the cost of site publishing.

You can use this feature with: site-builder publish-quilts --epochs=<EPOCHS> <YOUR-BUILD-DIR>.

⚠️ Important note: This feature is only available when building site-builder from source with cargo build --features quilts-experimental.

Changes​

  • site-builder: Publish using quilts.
  • portal: Derive quiltpatchid for resource retrieval.
  • portal: Retrieve quilt-based resources.
  • portal: Update domain parsing logic and tests for parse-domain@8.2.2.
  • site-builder: Add more checks for tx failure.
  • site-builder: Update the site name if changed in ws-resources.json.
  • site-builder: Override walrus_package from config if passed explicitly as an argument.
  • site-builder: Catch errors earlier in site PTB.
  • Add workflow to build and publish the server-portal Docker image.
  • Create tarball for the site-builder binary in the release workflow.
  • Compress the site-builder tarball with gzip and use the .tgz extension.
  • Add a tarball creation step.
  • Add ubuntu-arm64 to the site-builder build list.
  • Optionally use --check-extend on the site deploy action.
  • Clean up portal code by removing the Sentry integration.
  • site-builder: Remove unused network.rs.
  • server-portal: Remove Vercel web analytics and Sentry remnants.
  • server-portal: Use mainnet as the default build-arg for suins in Dockerfile.

Walrus Sites walrus_sites_v0.1.0_1750076111_mainnet_ci​

June 16, 2025 | GitHub

🚀 Welcome to the very first official release of Walrus Sites! This marks the production-ready milestone for the project.

Starting with this release, each version will include all the necessary components for deploying (via the site-builder) and accessing (via the portals) your Walrus Sites.

We are committed to following semantic versioning conventions for all future releases, ensuring clarity and consistency in version updates.

Changes​

  • site-builder: Added an expiration column for site resources when running the sitemap.
  • site-builder: Introduced --end-epoch and --earliest-expiry-time flags for defining resource end-epochs.
  • site-builder: Implemented a deploy command to consolidate the publish and update commands.
  • portal: Added a custom 404 fallback template and integrated it into the URL fetching logic.
  • site-builder: Old deletable blobs are now removed after updates.
  • site-builder: Updated browsing options based on network context.
  • site-builder: Ensured metadata updates when modifying an existing site.
  • site-builder: Enforced the site_name field and improved the default naming.
  • site-builder: Fixed issues with commented values in the configuration.
  • portal: Restructured portal logs for better organization.
  • contract: Added a README for MVR.
  • Added Sonar Analyzer to the CI pipeline for improved code quality checks.
